Nuri Agent Design System

One small contract for the actual app. It covers the wallet, bitcoin, card, modal, QR, transaction, input, and status patterns used in ../nuri-expo.

If a UI element is not here or in agent-design-system.json, future agents should not invent it during product work.

Prime Rule

Plain text is never clickable. Plain icons are never clickable. Clickable text is TextLink. Clickable icons are IconButton. Commands are Button.

Rows are clickable only when the whole row is an owned primitive like InfoList, TransactionList, dropdown, or choice sheet row.

Main Balance Tab Pattern

  • ScreenHeader with optional small header Button and support IconButton.
  • BalanceScreenLayout centers the main balance and action row.
  • TappableBalance is the only clickable balance treatment.
  • Two large quick actions: receive/details and send/add.
  • FloatingTransactionStatus owns pending state and transaction access.
  • Feature work opens through modals, not through hidden clickable text.

Do

  • Use Button for commands.
  • Use IconButton for icon-only commands.
  • Use TextLink only inline in body copy.
  • Use owned row primitives for row actions.
  • Keep cards informational unless the named primitive owns the interaction.

Do Not

  • Do not wrap text in raw Pressable or TouchableOpacity.
  • Do not wrap raw icons in raw pressables.
  • Do not make cards clickable.
  • Do not invent new input, list, or button styles.
  • Do not make non-clickable status look like an action.

Agent Checklist

  • Pick one screen pattern: balance tab, modal form, choice sheet, detail list, transaction list, QR flow, or card carousel.
  • Use only components listed in agent-design-system.json.
  • Use only tokens from ../nuri-expo/designSystem.ts.
  • Every clickable element must be one of the allowed clickable surfaces.
  • Every non-clickable element must not look clickable.
  • Use one primary action in the visible area.
  • If the needed component is missing, update this contract first.
